## Additional findings — 2026-10-14

1. **Obsolete Gazebo plugin reference**
   Removed the ROS 1 `libgazebo_ros_control.so` reference because it is incompatible with this ROS 2 Humble setup. The existing Gazebo differential-drive plugin provides drive control.

2. **Malformed IMU configuration**
   Corrected an extra closing angle bracket in the IMU sensor configuration.

3. **LiDAR topic configuration**
   Configured `libgazebo_ros_ray_sensor.so` with the LaserScan output type and remapped `~/out` to `/scan`.

4. **LiDAR frame**
   Added `frame_name=lidar_link_1`. Verified that `/scan` publishes messages carrying this frame ID and that TF resolves `base_footprint` to `lidar_link_1`.

5. **RViz grid configuration**
   Investigated grid placement through RViz display properties. This was a visualization/reference-frame issue, not proof of an incorrect robot spawn pose.

## Issues not conclusively resolved

- RViz reported a timestamp-related message-filter warning. Both RViz and robot_state_publisher have use_sim_time enabled; the warning's root cause remains unconfirmed.
